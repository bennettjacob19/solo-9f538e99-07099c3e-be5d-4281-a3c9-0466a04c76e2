# 窄带组播补传演练

站台终端在窄带组播中漏收绕行图，本网页用于本地补传演练。

## 玩法

1. **上传新图**：按 4 KiB 切块，至多 8 块（即 ≤ 32 KiB），末块补零、重组按原长截断。
2. **登记终端**：启用 2~4 台，勾选每台首播实收的块号。
3. **逐轮补传**：每轮设定广播帧数上限和各终端的异或解码额度。一帧发一个
   原块或两块异或；终端实收异或帧、恰缺一块且解码额度未用完时才解回缺块。
   按本轮无丢帧推算，只要有一串单块或异或帧能在帧数与各站解码额度内让各站
   收齐，就选出最短的一套实发；确实无解才报无方案并保留各站已收块。可注入
   某台终端漏收本轮某帧。
4. 页面列出实发帧、各站缺块与解码次数；下一轮按各站实收和解回的块继续补传。
5. 每台终端独立拼图，SHA-256 与新图相符才替换可下载的旧图。

## 并发约定

- 规划计算不占用全局锁：规划期间无需等计算结束，即可下载终端当前图、上传
  新图、登记终端并开始新一轮补传。
- 每次状态变更（新图载入、终端登记、轮次落地、重置）推进单调递增的纪元号；
  规划完成时纪元已变的旧规划结果一律丢弃：不发帧，也不改轮次记录、终端
  进度与下载图。
- 同一服务所有并发规划留存的搜索状态合计不超过 30 万（`SEARCH_NODE_CAP`），
  预算耗尽时仅退化为少缓存，不影响"有解必找到"。

## 启动

```bash
docker compose up --build      # 或：pip install -r requirements.txt && python app.py
# 打开 http://localhost:5000
```

## 测试

```bash
python -m pytest tests/ -q
```

## 结构

- `planner.py`：切块/重组、迭代加深帧序列规划（单块前置规范化 + 启发式剪枝 +
  转置表，限帧数+限解码，有解必找到）、轮次执行（含漏帧注入）
- `app.py`：Flask 页面与状态流转（规划期释放全局锁，纪元号丢弃过期规划）
- `templates/index.html`：单页界面
- `tests/test_drill.py`：切块、紧额度、8 块×4 终端、漏帧补传、并发与全流程测试
